# 功能范围与交付路线

## 1.0 产品定义

1.0 是可供他人独立部署的单站点个人出版系统。它提供一个唯一站主账户、现代管理后台、文章与页面、可上传主题、受控官方插件和完整自托管运维能力；它不是多租户平台、会员商业系统或通用 Headless CMS。

## 功能归属

### 核心

- 首次安装向导、唯一站主、密码、强制 TOTP、恢复码与 CLI 恢复。
- 文章、页面、Markdown 可视化/源码编辑、15 秒编辑快照。
- 草稿、定时、发布、撤回、30 天回收站。
- 不可变版本、最近 50 个普通版本、永久发布检查点。
- 单分类、多标签、独立导航和固定永久链接。
- 本地媒体库、响应式图片、引用保护、本地存储。
- 宋韵山水默认主题、主题上传、预览、验证、原子切换。
- 公开页面快照缓存、ETag、压缩配合和静态资源指纹。
- SQLite FTS5 中英文搜索。
- Canonical、社交元数据、JSON-LD、RSS、Sitemap、robots 和重定向。
- 结构化日志、健康检查、状态页、审计与零默认遥测。
- 完整备份、恢复演练、向前迁移、升级预检。
- 开放归档和 Markdown 导入导出。

### 默认关闭的官方插件

- 本地评论或外部评论提供方。
- 隐私型本地聚合统计。
- S3 兼容媒体/备份存储。
- SMTP 通知和外部 Newsletter 表单。
- 只读内容 API。
- 签名 Webhook。

### 离线工具

- WordPress WXR 导入。
- Ghost JSON 导入。
- Markdown 目录/ZIP 导入。
- 完整备份检查、恢复、媒体迁移和认证重置。

## 明确不做

- 多租户、多站点、官方托管、计费或在线市场。
- 协作者、角色、自定义权限、读者账户或付费会员。
- 自定义内容类型、层级分类或自定义分类法。
- 多语言内容关联和语言前缀路由。
- 任意永久链接模板。
- 任意服务端插件上传、Go 动态插件、Lua 或通用脚本。
- 页面搭建器、任意 header/footer 代码注入。
- 内建视频转码、邮件群发基础设施或支付。
- GraphQL、公开写 API、向量搜索或独立搜索服务。
- Redis、消息队列、微服务和默认 PostgreSQL。

## 阶段一：核心闭环

目标是能安全写作、发布、阅读、备份和重新启动，而不是先搭空框架。

纵向切片顺序：

1. 程序骨架、配置、SQLite、迁移、健康检查和 Compose。
2. 初始化唯一站主、密码/TOTP、会话、CSRF 与 CLI 恢复。
3. 文章草稿从编辑到公开永久链接的完整路径。
4. 默认主题、Markdown 清洗、页面缓存和渲染版本失效。
5. 页面、分类、标签、导航与媒体本地上传。
6. 版本、编辑快照、定时发布、撤回和回收站。
7. SEO、RSS、Sitemap、重定向与搜索。
8. 完整备份、恢复演练、升级前恢复点与审计。

阶段验收：新用户可用 Compose 启动，在无邮件和外部服务条件下完成初始化、写作、发布、搜索、换配置、备份、清空实例并恢复；默认主题通过性能与无障碍基础门槛。

## 阶段二：完整博客能力

1. 主题包安装、安全验证、预览、原子切换和回退。
2. 插件宿主、设置 schema、管理菜单、事件和持久任务。
3. 本地评论与外部评论互斥提供方。
4. 本地统计、状态面板与数据保留任务。
5. S3 存储、SMTP 通知、外部 Newsletter 适配。
6. 开放归档往返、媒体存储迁移与重定向管理。

阶段验收：禁用全部插件时内存和路由不因插件显著增长；任一插件失败不影响文章发布；主题损坏始终能回退默认主题；本地与 S3 间媒体迁移经校验可逆。

## 阶段三：生态与发布加固

1. WordPress WXR、Ghost JSON 和 Markdown 离线导入器及 dry-run 报告。
2. 只读内容 API 与签名 Webhook。
3. 主题开发手册、视图模型参考、测试夹具和示例主题。
4. 插件 Host API 文档、官方插件契约和事件版本策略。
5. Linux amd64/arm64 容器与跨平台 CLI 发行物、SBOM、校验和。
6. 安全审计、依赖许可证审查、备份恢复演练。
7. 既定规模的延迟、吞吐、RSS、缓存、搜索和大媒体测试。
8. Chromium、Firefox、WebKit 的核心流程、视觉和 ARIA 回归。

阶段验收：全新安装、逐版本升级、升级失败恢复、导入真实样本、长期任务重试、主题兼容和所有 ADR-0031 指标均有自动化证据。

## 发布质量门槛

每个候选版本必须通过：

- `go test`、race 测试、静态分析和关键解析器 fuzz 测试。
- SQLite 从上一受支持版本向前迁移，以及从升级前备份完整恢复。
- 主题样例矩阵：空站、长文、中文英文混排、大图、无封面、长标签、404。
- Playwright 核心后台与公开流程、键盘操作和 ARIA 快照。
- 一核一 GiB 容器中的内存、100 RPS 缓存、搜索和首次渲染基准。
- 默认主题 CSS/JS 体积与 Core Web Vitals 实验室预算。
- 依赖漏洞、容器镜像、SBOM 和 Apache-2.0 兼容性检查。
- 备份校验与一次隔离环境恢复演练。

未达到门槛的功能可以保持实验或延后，不能通过提高既定资源预算来掩盖回归。

## 首个实现里程碑的完成定义

不是“代码已经合并”，而是站主能够在一台空白 1 核 1 GiB Linux VPS 上：

1. 通过固定版本 Compose 启动 HTTPS 站点。
2. 初始化唯一站主并绑定 TOTP。
3. 创建带图片的 Markdown 文章，预览、发布并通过永久链接访问。
4. 修改文章后查看版本，撤回并重新发布。
5. 通过搜索、分类、标签、RSS 和 Sitemap 发现内容。
6. 创建完整备份，在另一个空数据目录恢复并得到相同公开结果。
7. 查看健康状态、日志和失败任务，且默认没有任何外发遥测。

达到该闭环后才扩展评论、统计、API 和迁移生态。

## 主要风险与缓解

| 风险 | 缓解 |
|---|---|
| 可视化编辑器改写 Markdown | 保存前往返夹具、未知指令退回源码、正文差异预览 |
| 纯 Go 图片处理造成内存峰值 | 头部限额、像素上限、并发 1、基准门、失败保留原图 |
| SQLite 长写事务阻塞 | 单写连接、短事务、外部 I/O 提交后执行、WAL checkpoint 监控 |
| 全局渲染版本导致冷缓存 | 发布后预热首页和当前内容，其余按需生成；先保证正确失效 |
| 主题破坏站点 | 安全解包、全模板解析、样例渲染、原子切换、内嵌默认主题 |
| 插件边界逐渐泄漏 | Host 能力白名单、禁止裸 DB/FS、契约测试和 API 版本审查 |
| 功能范围再次膨胀 | 新需求必须归入核心、官方插件或明确非目标，并用 ADR 解释硬边界变化 |
