# 插件 Host API 与事件策略

插件是随发行物编译的可信 Go 代码，不能上传任意服务端程序。插件实现：

```go
type Plugin interface {
    Manifest() Manifest
    Register(*Host) error
}
```

Host API 当前版本为 `1`，只暴露插件自己命名空间下的公开/后台路由、宿主声明的公共路由槽、设置 schema、提交后事件订阅、持久任务、菜单和宿主日志能力。Host 不暴露裸 `*sql.DB`、通用文件系统、进程执行器或任意模板集合；可信 Go 插件不受进程沙箱隔离。

公开路由默认必须位于 `/plugins/{plugin-id}/`；兼容评论、Newsletter 和只读内容 API 的旧公共路径只能通过宿主声明的 `RouteSlot` 注册。管理路由由 `AdminRoute` 自动收敛到 `/admin/plugins/{plugin-id}/`，并在启用检查下执行；方法/路径重复或越界注册会被拒绝。

设置 manifest 带 `settingsVersion`。宿主限制 schema 字段、类型、URL/颜色/媒体 ID、单值长度和总 JSON 大小（64 KiB）；敏感字段读取只返回 `••••••`，提交该占位符或空值不会覆盖原值。版本变化必须提供迁移函数，迁移失败时插件保持禁用且旧 JSON/schema_version 不变。

## 事件版本

事件名称使用 `Name.vN`，例如 `ContentPublished.v1` 和 `CommentApproved.v1`。订阅带版本匹配；事件只携带公开对象 ID、版本和小型元数据。新增可选字段保持兼容；删除字段或改变语义必须发布 `v2`，旧任务载荷在整个受支持升级窗口内仍可解码。未知事件版本不会调用不匹配的插件处理器。

同步订阅只能登记快速本地工作；邮件、Webhook、远程 API、重计算都必须先写入持久任务。任务定义包含 payload 版本和上限（默认 64 KiB，宿主总上限 64 KiB），kind 自动带 `plugin:{id}:` 前缀；任务具有幂等键、短租约、最多五次指数退避，进程崩溃后可重新执行；达到上限后进入 `failed` 并在状态页可见。

需要和业务写入保持原子性的插件，必须使用带 `*sql.Tx` 的入队 API：在同一短事务中写入插件状态、`event_outbox` 或插件投递记录，再登记持久任务。提交前失败时所有记录一起回滚；提交后由任务处理器在事务外执行副作用。处理器必须可重入，并用稳定幂等键防止重启或并发造成重复效果。

插件应把无法通过重试修复的配置或策略错误标记为永久失败，例如被宿主网络策略阻断的地址、无效的远端契约或不可接受的响应；永久失败直接进入 `failed`，但保留原任务供管理员从运维页显式重试。不要把秘密、原始地址、令牌、邮箱或完整远端响应写入任务错误、日志或审计。

## 官方契约

官方插件包括本地/外部评论、隐私统计、只读内容 API、签名 Webhook 和 Newsletter。S3 与 SMTP 是启动配置选择的适配器，不在插件管理页启停。评论提供方互斥；所有可选插件默认关闭。禁用插件会撤销路由和事件接收，但保留配置与数据，后台删除仅持久化移除状态并停用插件，保留配置、业务数据和待处理任务；重新添加后保持停用。即使显式启动配置要求启用，已删除插件也不会在重启后自动恢复。删除业务数据另行备份并确认。

插件初始化先在临时注册表登记路由、菜单、事件和任务，全部成功后一次性合并；失败不留下半成品。插件被禁用时，宿主不消费其任务、不调用其事件订阅，也不执行外发；相关数据和待处理任务保留，重新启用后继续处理。事件没有任何启用的订阅者时可以标记为已完成，避免停用插件造成永久积压。
