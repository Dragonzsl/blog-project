# 澄光编辑室主题设计

状态：设计方案，已实现主题包 v1.0.0
主题 ID：`luminous-editorial`
主题名称：澄光编辑室 / Luminous Editorial
设计版本：1.0
更新日期：2026-09-18

## 1. 设计结论

新增一套独立主题，不修改默认主题，也不替换已有的 `cel-panel` 主题。澄光编辑室把个人博客当作一件“持续发布的作品”来设计：访客先看到站点主张，再通过精选内容进入阅读，最后通过内容光谱、分类和归档继续探索。

视觉上参考 Apple 官网的产品叙事方式，而不是复制 Apple 的品牌资产：大尺度主张、连续滚动章节、克制的系统字体、明确的单一主操作和有空间感的动效。主题的独特识别点是“内容光谱”：用一条由文章节点组成的轻量轨道表达博客内容的时间与主题关系。

本方案优先使用现有主题 API 和公开视图模型，不需要数据库迁移、路由变更或新的业务字段。内容光谱第一版由首页已有的精选文章、最近文章、分类和归档数据组成；如果未来需要真正按主题聚类的二维关系图，再单独评估视图模型扩展。

## 2. 目标与非目标

### 目标

- 让首页在首屏内表达“这里写什么、为什么值得读、从哪里开始”。
- 让文章阅读成为最稳定、最安静、最清晰的体验。
- 用少量有意义的动效增加灵动感，不依赖动画才能理解内容。
- 同时适配浅色、深色、移动端、键盘操作和无 JavaScript 场景。
- 不请求第三方字体、图标、分析脚本或 CDN 资源。
- 主题可独立打包、上传、预览、激活和回退。

### 非目标

- 不复制 Apple 标志、产品图形、文案或专有界面。
- 不制作 SPA、全屏滚动锁定、自动播放视频或复杂的 3D 场景。
- 不改变文章、页面、评论、Newsletter、搜索和 SEO 的业务语义。
- 不把主题变成插件；主题只负责展示，不增加服务端能力。

## 3. 设计原则

### 3.1 内容先于装饰

每个视觉元素都必须帮助访客判断“读什么、为什么读、读完还能去哪”。渐变、光晕、轨道和动画只承担引导作用，不替代标题、摘要或链接。

### 3.2 Hero 是站点主张

首页第一屏不是文章列表的放大版，而是站点的编辑宣言。站点名称、短句、描述和一个进入最新内容的操作构成主叙事。没有站点简介时，Hero 仍然保持简洁，不生成虚构文案。

### 3.3 一处大胆，其余克制

唯一的明显创意是内容光谱。导航、文章正文、表单和错误页保持安静，避免光晕、圆角、阴影和动效同时竞争注意力。

### 3.4 动效表达空间关系

动效只表达进入、聚焦、展开、阅读进度和继续探索。默认不使用视差滚动和滚动劫持；`prefers-reduced-motion: reduce` 下直接呈现最终状态。

### 3.5 系统感来自一致性

按钮、链接、焦点、卡片、标题、时间、标签和目录使用同一套 token。主题允许内容有个性，但不允许组件各自发明视觉语言。

## 4. 品牌与视觉方向

### 4.1 气质

澄光编辑室应给人的感受是：清醒、轻盈、有秩序，但不是冷冰冰的企业官网；像一个正在持续更新的个人工作室，而不是内容管理系统的前台。

### 4.2 颜色 token

颜色使用语义 token，不在组件中直接散落颜色值。

| 语义 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--paper` | `#F7F8FA` | `#0D0F12` | 页面背景 |
| `--surface` | `#FFFFFF` | `#171A20` | 卡片、抽屉、表单 |
| `--ink` | `#15171A` | `#F5F7FA` | 主文字 |
| `--muted` | `#6F747C` | `#AEB5C0` | 摘要、时间、辅助说明 |
| `--line` | `#E4E7EB` | `#303640` | 分隔线、边框 |
| `--accent` | `#6C5CE7` | `#A79BFF` | 主操作、当前状态 |
| `--accent-strong` | `#5142C7` | `#C1B9FF` | hover、焦点强化 |
| `--accent-soft` | `#EEECFF` | `#252238` | 柔和底色 |
| `--glow-blue` | `#8BC8FF` | `#416F9E` | Hero 光晕 |
| `--glow-pink` | `#F6A9D7` | `#8B526F` | Hero 光晕 |
| `--danger` | `#B42318` | `#FFB4AB` | 错误、危险状态 |
| `--code-bg` | `#1B2028` | `#080A0D` | 代码块背景 |

建议的渐变只出现在 Hero 和精选文章视觉层：`accent → glow-blue → glow-pink`，透明度较低，不作为正文背景。

### 4.3 字体

不引入远程字体，遵守项目“默认零第三方资源”的约束。

- 展示标题：`-apple-system, BlinkMacSystemFont, "SF Pro Display", "PingFang SC", "Noto Sans CJK SC", sans-serif`
- 正文：`-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC", "Noto Sans CJK SC", sans-serif`
- 标签与数据：`ui-monospace, SFMono-Regular, Menlo, Consolas, monospace`

标题使用较重字重、紧字距和流体字号；正文维持 16–18px 和约 1.75 的行高，避免为了“像发布页”牺牲长文阅读。

### 4.4 几何与质感

- 内容最大宽度：`1200px`。
- 阅读宽度：`720–760px`。
- 页面横向安全边距：`clamp(20px, 5vw, 64px)`。
- 大模块圆角：24px；普通卡片：16px；按钮：999px。
- 阴影只用于浮层和精选卡片，颜色使用黑色低透明度，不使用厚重拟物阴影。
- 线条使用 1px，透明度和背景形成层次，不使用大量装饰性边框。

## 5. 信息架构与页面地图

```text
首页
├── Hero：站点主张
├── 精选文章：最重要的一篇内容
├── 内容光谱：最近内容与分类入口
├── 最近文章：时间顺序阅读入口
├── 站点简介 / 归档入口
└── Newsletter / 页脚

文章页
├── 顶部阅读进度
├── 返回与文章元信息
├── 标题、摘要、封面
├── 正文与浮动目录
├── 复制 / 分享 / 打印
├── 上一篇 / 下一篇 / 相关文章
├── 评论 / Newsletter
└── 页脚

集合页
├── 分类或搜索 Hero
├── 首条内容突出
├── 其余内容列表
└── 分页

目录页
├── 分类
├── 标签
└── 年 / 月归档时间线
```

全站导航保持两层以内。桌面端显示简洁顶部导航；较窄屏幕使用右侧或左侧抽屉。抽屉、目录和主题切换必须共用现有的键盘、焦点和关闭语义。

## 6. 首页设计

### 6.1 Hero

```text
┌──────────────────────────────────────────────────┐
│ 站点名                         文章 归档  搜索 ◐ │
├──────────────────────────────────────────────────┤
│                                                  │
│  PERSONAL NOTES / 持续更新                       │
│                                                  │
│  把值得留下的东西，                               │
│  写得更清楚。                                     │
│                                                  │
│  一段站点简介，最多两行。      [阅读最新文章 →]    │
│                                                  │
│                     ◌  内容光谱                 │
└──────────────────────────────────────────────────┘
```

如果存在 `.Home.About`，可以使用其标题或摘要作为简介入口；没有 About 内容时，使用站点元数据，不在主题内硬编码与站点无关的宣传语。

Hero 的视觉层由一个 SVG/CSS 光晕组成，光晕不承载信息，屏幕阅读器隐藏。首屏只安排一个主 CTA，次级入口使用普通文字链接。

### 6.2 精选文章

精选文章像一个“当前主打内容”模块：

- 左侧为类型、分类、发布时间和阅读时间。
- 中间为大标题和摘要。
- 右侧或底部为“开始阅读”。
- 有封面时使用低饱和背景图并预留比例，避免 CLS。
- 无封面时使用 CSS 光谱背景，不显示空白图片占位。

卡片 hover 只移动 2–4px，并让背景光晕轻微偏移；键盘 focus 与 hover 视觉等价。

### 6.3 内容光谱

内容光谱是主题的签名模块，不是强制的复杂图表。

桌面端：

- 使用一条横向 SVG 轨道。
- `.Home.Featured`、`.Home.Recent` 和 `.Home.Categories` 映射为节点。
- 节点大小表达入口层级，不表达未经数据支持的热度。
- 节点必须是可访问链接，文字标签在视觉上可见或通过可见 tooltip 辅助。

移动端：

- 退化为横向轨道 + 可换行的节点列表，禁止页面级横向滚动。
- 若可用宽度不足，使用纵向时间线。
- 不依赖 hover 才能知道节点含义。

### 6.4 最近文章

采用“日期轴 + 文章标题 + 摘要”的纵向结构，最新内容有一个小型强调点。每条内容使用完整链接区域，点击目标至少 44×44px。文章标题最多三行，摘要最多两行，避免首页被单篇长标题撑开。

### 6.5 站点简介与归档

底部采用左右分栏：左侧显示站点简介或 About 入口，右侧显示归档月份和文章总入口。视觉重量低于精选文章，不使用单独的营销 CTA。

## 7. 文章页设计

文章页的核心目标是“让读者安静读完”。

```text
阅读进度 ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

← 返回文章                         本文目录

ARTICLE / 文章
一个足够有空间感的标题
摘要说明文章要解决的问题或分享的观点。
2026年09月18日 · 8 分钟阅读 · 分类 / 标签

                  [封面或抽象视觉]

正文正文正文正文正文正文正文正文
正文正文正文正文正文正文正文正文

复制链接   分享   打印

上一篇                         下一篇
相关文章 / 评论 / Newsletter
```

设计要求：

- 正文列宽控制在 720–760px，长屏幕上目录固定在侧边但不遮挡正文。
- 标题字号随视口流体变化，中文标题避免过度压缩字距。
- 正文中的链接、代码、引用、表格和图片沿用现有安全 Markdown 输出。
- 目录在桌面端可见，在窄屏幕由按钮打开抽屉。
- 阅读进度只反映正文滚动，不反映整个页面的页脚和评论区。
- 图片必须使用已有宽高、`srcset` 和 lazy/eager 策略；第一张封面预留尺寸。

## 8. 集合、搜索、目录与状态页

### 集合页

顶部显示集合标题和描述；第一篇内容以精选形态展示，后续内容使用日期轴列表。列表页不要重复首页的大型光晕。

### 搜索页

搜索输入框采用 Spotlight 风格的单一主输入：标签清晰可见、支持键盘提交、筛选项以轻量控件呈现。结果显示标题、摘要、内容类型、发布时间和阅读时间。无结果页必须提供清空筛选、分类和归档入口。

### 目录页

分类使用三列网格，标签使用可换行的胶囊链接，归档使用年份标题 + 月份时间线。数据为空时说明“发布内容后这里会自动出现什么”，并提供回到首页或搜索的动作。

### 状态页

404、服务不可用和预览错误共用同一套大标题结构：状态码、明确说明、一个主要回退动作。不要展示堆栈、内部路径或空白错误页。

## 9. 交互与动效规格

### 动效 token

```css
--ease-standard: cubic-bezier(.22, 1, .36, 1);
--motion-fast: 160ms;
--motion-base: 280ms;
--motion-emphasis: 520ms;
```

推荐行为：

| 场景 | 动效 | 时长 |
| --- | --- | --- |
| 首屏 Hero | 标题与说明依次淡入、上移 12px | 420–560ms |
| 精选卡片 hover | 上移 3px，光晕偏移 | 220–280ms |
| 文章列表进入 | 只对首屏附近项目做轻微淡入 | 280–360ms |
| 抽屉打开 | 平移 + 不透明度 | 280ms |
| 目录当前项 | 颜色和细线变化 | 160ms |
| 阅读进度 | 直接更新宽度 transform | 无过渡或极短过渡 |

禁止：

- 自动播放视频或无限循环大面积动画。
- 通过 JS 改变 `width`、`height` 造成布局抖动。
- 让页面必须滚到某个位置才能继续操作。
- 同一视图中同时启动超过两个主视觉动画。

`prefers-reduced-motion: reduce` 下：移除入场、视差、光晕移动和滚动触发动画；保留焦点、展开、关闭等必要状态变化，并直接渲染最终状态。

## 10. 响应式规格

| 视口 | 布局策略 |
| --- | --- |
| 375–767px | 单列，导航抽屉，Hero 左对齐，内容光谱纵向化，正文 16px |
| 768–1023px | 单列主内容 + 轻量双列模块，目录抽屉，精选内容保留封面 |
| 1024–1439px | 12 列网格，顶部导航，目录可固定在正文外侧 |
| 1440px 以上 | 扩大留白和视觉层，不无限放大正文；光谱显示完整轨道 |

所有断点都必须满足：无水平溢出、文本可缩放、点击目标至少 44×44px、焦点不被 sticky/fixed 元素遮挡。

## 11. 现有主题 API 映射

第一版不增加业务视图字段，使用现有公开数据：

| 主题区域 | 数据来源 |
| --- | --- |
| 站点名与导航 | `SiteName`、`Navigation` |
| Hero 简介 | `Meta.Description`、`Home.About` |
| 精选文章 | `Home.Featured` |
| 最近文章 | `Home.Recent` |
| 内容光谱节点 | `Home.Featured`、`Home.Recent`、`Home.Categories`、`Home.Archive` |
| 分类入口 | `Home.Categories` 或 `Directory.Categories` |
| 标签入口 | `Directory.Tags` |
| 时间线 | `Home.Archive`、`Directory.ArchiveYears` |
| 文章目录 | `Article.TOC` |
| 上下篇与相关文章 | `Article.Previous`、`Article.Next`、`Article.Related` |
| 评论与 Newsletter | `Features` 与标准插槽 |
| 主题个性化 | `Settings` |

主题不得读取环境变量、数据库、文件系统、内部 ID、草稿、编辑快照或插件秘密。关键词高亮和正文 HTML 继续由核心负责安全处理。

```text
themes/luminous-editorial/
├── theme.json
├── LICENSE
├── preview.webp
├── templates/
│   ├── theme_shell.html
│   ├── navigation.html
│   ├── home.html
│   ├── listing.html
│   ├── article.html
│   ├── search.html
│   ├── directory.html
│   ├── status.html
│   └── pagination.html
└── assets/
    ├── theme.css
    └── theme.js
```

建议初始 manifest：

```json
{
  "id": "luminous-editorial",
  "name": "澄光编辑室",
  "version": "1.0.0",
  "themeApi": 1,
  "core": ">=1.0.0 <2.0.0",
  "features": ["dark-mode", "toc", "responsive", "comments", "newsletter"],
  "settingsVersion": 1,
  "settingsSchema": {
    "accent": {"type": "color", "default": "#6C5CE7"},
    "showSpectrum": {"type": "boolean", "default": true},
    "showReadingTime": {"type": "boolean", "default": true}
  }
}
```

设置只改变展示，不改变内容语义。封面仍然优先使用文章公开视图中的 `MediaData`；不允许把原始媒体对象、文件路径或对象存储 key 交给模板。

CSS 和 JS 必须遵守现有预算：压缩后的 CSS 不超过 40 KiB，阅读必需 JavaScript 不超过 15 KiB。`theme.js` 只负责主题切换、抽屉、目录、高亮、阅读进度、复制/分享/打印和必要的渐进增强。

## 13. 实现分期

### Phase 1：视觉骨架

- 建立主题目录、manifest、公共壳层和 token。
- 完成首页 Hero、精选文章、最近文章和文章页。
- 完成浅色、深色、无 JS 和移动端基础状态。

### Phase 2：完整页面

- 完成集合、搜索、目录、状态页和分页。
- 接入评论、Newsletter、目录和文章操作插槽。
- 完成内容光谱的 SVG/CSS 渐进增强版本。

### Phase 3：质量门禁

- 增加主题专用渲染测试和固定夹具。
- 使用空站、单篇、长文、中英文混排、大图、无封面、长标题、无结果、404 和预览场景验证。
- 运行 `go test -tags 'fts5 sqlite_omit_load_extension' ./...`、`make vet`、浏览器三引擎回归和 `make perf-gate`。
- 打包 ZIP，安装、预览、激活、回退各跑一次，确认坏主题不会接管站点。

### Phase 4：可选视图模型增强

只有当内容光谱需要真实主题聚类、统计或更多内容关系时，才增加版本化公开字段。该阶段必须单独做 API 兼容性评估，不在主题实现阶段顺手扩展领域模型。

## 14. 验收标准

### 视觉

- 首页首屏能看到站点名、主张、简介和一个明确入口。
- 精选内容与普通文章有清楚层级，但不依赖阴影表达层级。
- 内容光谱是可理解的导航，不是装饰性动画。
- 浅色和深色模式均有足够对比度，主题色不刺眼。
- 375、768、1024、1440px 视口没有横向溢出。

### 可用性与无障碍

- 所有交互控件有可见焦点和可理解的名称。
- 图像有准确替代文本；装饰 SVG 使用 `aria-hidden`。
- 文章、导航、目录、表单使用正确语义元素。
- 键盘可以完成导航、打开/关闭抽屉、切换主题和操作文章。
- `prefers-reduced-motion` 下内容顺序和功能不变。
- 正文和主要控件文字达到至少 4.5:1 对比度。

### 性能与安全

- 首屏不依赖第三方网络资源。
- 图片有尺寸预留，首屏封面不造成明显 CLS。
- JS 失败时页面仍可读、可导航、可提交表单。
- 模板只使用安全公开视图，不新增 `safeHTML` 绕过。
- CSS、JS、模板和预览资源在主题 ZIP 限制内。
- 主题安装失败或激活失败时，当前主题和默认主题仍可用。

## 15. 设计取舍记录

1. 选择“系统无衬线 + 大标题”，而不是远程编辑字体：保证中文显示、首屏性能和离线自托管一致性。
2. 选择“内容光谱”而不是大型 3D 视觉：它能从现有数据生成，能降级为时间线，也不会让博客变成展示动画。
3. 选择独立主题而不是重写默认主题：保留安全回退，降低发布风险，也方便与 `cel-panel` 并存。
4. 选择滚动叙事的节奏而不是滚动劫持：借鉴 Apple 的叙事感，但保证读者可以直接跳转、搜索和使用浏览器原生行为。
