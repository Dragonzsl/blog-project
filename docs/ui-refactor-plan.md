## 1. 目标

当前站点已经具备首页、文章详情、分类、标签、搜索，以及文章、页面、媒体、主题、插件、重定向和回收站等后台能力。本轮重构的重点不是继续堆叠首页装饰，而是把这些能力组织成一套更完整的“个人出版物”体验：

1. 读者能快速发现内容、进入阅读、继续阅读。
2. 站主能从一个工作台完成写作、发布、组织和维护。
3. 评论、Newsletter、统计等能力保持可插拔，不让默认站点变成社区平台。
4. 动效只强化层级和反馈，不牺牲首屏速度、可访问性和长文阅读。

## 2. 产品定位与设计方向

### 2.1 产品角色

- 主题：单站点、单站主、长期积累的独立写作空间。
- 主要读者任务：从首页或搜索进入一篇文章，并自然找到相关内容。
- 主要站主任务：快速写作，确认发布状态，维护内容组织和站点外观。

### 2.2 视觉方向

沿用当前的 quiet editorial 方向：克制、留白、适合长文；通过结构和文字层级体现高级感，而不是使用复杂背景或过度卡片化。

| 设计要素 | 方案 |
| --- | --- |
| 纸张底色 | `#f7f5ef`，暗色模式对应 `#111713` |
| 内容表面 | `#fffef9`，用于浮层、目录和表单区域 |
| 主文字 | `#18231d`，正文保持高对比度 |
| 苔绿色强调 | `#1c7352`，用于链接、进度、状态和行动按钮 |
| 辅助文字 | `#53625a`，用于日期、摘要和说明 |
| 字体 | 本地 CJK 衬线标题 + 本地无衬线界面文字，不依赖外部字体 CDN |

### 2.3 设计签名

用“阅读脊柱”作为全站的唯一记忆点：文章详情页顶部的阅读进度、目录当前位置和文章章节锚点都使用同一条苔绿色视觉线索。其余区域保持安静，避免每个组件都做动画。

## 3. 主流博客参考与取舍

| 产品 | 借鉴能力 | 本项目取舍 |

## 5. 公开页面重构

### 5.1 P0：首页

目标：从“文章列表入口”升级为“出版物首页”，但保持信息密度克制。

- 保留当前主标题和独立写作定位。
- 增加一篇精选文章；没有精选配置时回退到最新文章。
- 最近文章显示日期、分类、标签、摘要和阅读时间。
- 增加分类入口和归档入口，避免读者只能按时间顺序浏览。
- 增加“关于本站 / 关于作者”入口。
- 页脚显示 RSS；Newsletter 仅在对应插件启用后显示。
- 首页首屏不自动播放、不使用大图轮播。

建议结构：

```text
品牌导航
┌──────────────────────────────────────────────┐
│ 独立写作                                      │
│ 慢下来，把值得留下的写清楚。                  │
│ 站点简介                       [关于本站 →]   │
└──────────────────────────────────────────────┘

精选文章                                    查看全部 →
┌──────────────────────────────────────────────┐
│ 分类 · 日期       文章标题                    │
│                 摘要 / 阅读时间              │
└──────────────────────────────────────────────┘

最近文章        分类        归档        RSS
```

### 5.2 P0：文章详情页

目标：让文章本身成为完整的阅读终点和下一步入口。

- 顶部显示文章类型、分类、发布时间、更新时间和阅读时间。
- 生成 H2/H3 文章目录；桌面端固定在正文旁，移动端改为可折叠面板。
- 顶部增加轻量阅读进度条，进度与目录当前位置保持一致。
- 增加复制链接、系统分享、打印；不支持 Web Share API 时保留复制链接。
- 正文结束后增加上一篇、下一篇和相关文章。
- 评论区、Newsletter 区块使用插件插槽，未启用时不渲染空容器。
- 文章封面作为可选字段，不强迫每篇文章使用图片。


### 5.3 P0：搜索、分类、标签与归档

- 新增归档页，支持按年份和月份浏览。
- 增加分类索引和标签索引，展示数量、描述和最近文章。
- 分类/标签列表增加分页，不再只展示固定上限的数据。
- 搜索结果显示结果数量、关键词高亮、当前筛选条件和分页。
- 移动端将类型、分类、标签、排序收进可展开筛选面板。
- 无结果状态给出可执行建议：清空筛选、查看分类、查看归档。
- 搜索错误、空分类、空标签、无文章站点都使用明确的状态文案。

### 5.4 P1：分发和互动插槽

只在插件启用时出现：

- Newsletter：文章列表底部和文章正文后各提供一个低干扰订阅位置。
- 评论：文章底部显示评论列表、提交状态、审核提示和错误状态。
- 统计：公开端不展示追踪脚本状态；站主在后台查看隐私友好的统计。
- RSS：导航或页脚提供明确入口，不以弹窗打断阅读。

## 7. 跨页面状态设计

以下状态需要与正常页面同等设计，而不是最后补文案：

- 首次安装、无文章、无分类、无标签、无媒体。
- 搜索无结果、筛选无结果、搜索输入无效。
- 文章未找到、分类未找到、标签未找到、主题预览失败。
- 自动保存中、保存成功、保存失败、版本恢复成功。
- 插件未启用、插件异常、评论等待审核。
- 404 和 500 页面应提供返回首页、搜索和归档入口。

文案使用明确动词，例如“清空筛选”“创建第一篇文章”“恢复为草稿”，避免只显示“暂无数据”或“发生错误”。

## 8. 数据与路由前置工作

当前公共渲染数据主要包含类型、标题、slug、摘要、正文、日期、分类和标签。要支持本计划，需要先扩展公共视图模型，并保持主题与业务查询解耦。[公共视图模型](</Users/zhushilin/AI/blog-project/docs/reference/view-models.md>)

建议补充：

- `ReadingTime`、`UpdatedAt`、`Cover`。
- `TOC` 和稳定的标题锚点。
- `Previous`、`Next`、`Related`。
- `Pagination`、总数和当前筛选状态。
- 评论、Newsletter 等插件公开区块的 feature flags。
- `/archive`、分类索引、标签索引和分页查询。

查询层需要避免逐篇查询相关文章和媒体，相关文章、分类统计和分页数据应采用批量查询或缓存。

## 9. 动效与性能策略

### 9.1 允许的动效

- 页面首次进入时的短淡入。
- 文章列表 hover 时的轻微位移或苔绿色阅读脊柱展开。
- 目录展开/收起。
- 阅读进度条变化。
- 发布、保存、复制链接后的即时状态反馈。

### 9.2 明确禁止

- 自动播放视频、粒子背景、大面积视差和滚动劫持。
- 首屏轮播和必须等待 JavaScript 才能阅读的内容。
- 每个卡片同时使用缩放、阴影、位移和渐变。
- 默认引入外部字体、图标 CDN 或第三方追踪脚本。

### 9.3 性能和可访问性门槛

- 核心阅读和导航使用服务端 HTML，JavaScript 只负责渐进增强。
- 动画优先使用 `transform` 和 `opacity`。
- 支持 `prefers-reduced-motion`。
- 所有交互控件触控区域不小于 44px。
- 键盘焦点清晰，正文和控件保持足够对比度。
- 移动端 375px 宽度不出现横向滚动。
- 继续遵守主题 CSS、阅读端 JavaScript 和资源加载预算。[主题开发规范](</Users/zhushilin/AI/blog-project/docs/development/themes.md>)

#### 3A. 全站亮色/暗色模式开关（P0）

- 在公开站点导航和后台顶栏放置同一套主题开关，使用太阳/月亮 SVG 图标加当前状态文本；控件至少 44×44px，具备可见焦点、`aria-pressed`、`aria-label` 和键盘操作。
- 主题状态使用 `data-theme="light|dark"` 驱动现有 CSS token。首次访问跟随 `prefers-color-scheme`，用户主动选择后持久化到 `localStorage`；公开端和后台共用同一个键名，跨页面保持选择。
- 在首屏尽早读取已保存主题，避免刷新时先闪现另一套配色；只增加极小的同源初始化逻辑，不引入阻塞型依赖。同步更新 `color-scheme` 和 `theme-color`，让浏览器控件和地址栏颜色跟随主题。
- 逐项补齐暗色状态：页面底色、浮层、卡片、表单、通知、标签、代码块、目录侧栏、编辑器面板、边框、禁用态和焦点态。普通文字对比度至少 4.5:1，焦点指示与相邻背景保持清晰区分。
- 切换只做颜色和极短的 opacity 过渡；`prefers-reduced-motion: reduce` 下取消过渡。主题切换不触发页面重新加载、不改变滚动位置，也不覆盖用户正在填写的表单。

#### 3B. 代码片段语言标识与一键复制（P0）

- 在 Markdown 渲染阶段保留围栏代码的语言信息，例如 ` ```go ` 生成受控的 `language-go` 元数据；没有语言时显示“纯文本”，未知语言显示规范化后的文本标签，不直接输出未经校验的用户值。
- 将每个 `pre` 渲染为一个独立代码块组件：顶部显示语言标签和“复制代码”按钮，正文仍由原始 `<code>` 展示，避免把工具栏文字复制进去。只增强围栏代码，不给行内 `code` 增加复制按钮。
- 复制优先使用同源安全上下文中的 Clipboard API，失败时回退到隐藏 `textarea` 的传统复制方式；成功、失败和权限拒绝均在按钮附近提供 `role="status"` 的即时反馈，并支持键盘触发。
- 采用事件委托处理多个代码块，避免每个片段创建独立监听器；不引入 Prism、Highlight.js 等大依赖，不在首屏加载额外脚本。代码区域保留横向滚动，长 token 使用合理换行策略，不能撑破移动端。
- 增加 Markdown 渲染单测和浏览器回归：验证语言显示、复制内容与源代码逐字一致、无语言回退、复制失败提示、键盘焦点和 `prefers-reduced-motion`。

#### 3C. 文章目录移至侧边（P0）

- 桌面端将文章详情改为“目录侧栏 + 正文阅读列”的网格：目录宽约 220–240px，正文保持 65–75ch 的可读行长，二者之间保留 40–64px 间距。目录使用 `position: sticky`，最大高度为视口减去顶栏安全间距，过长时仅目录自身滚动。
- 目录 DOM 只保留一份，继续复用现有 H2/H3 锚点和 `IntersectionObserver` 高亮；给标题增加 `scroll-margin-top`，避免固定进度条或顶栏遮挡目标章节。当前章节同时提供 `aria-current="location"`。
- 桌面端不再把目录作为正文顶部的大块内容。移动端因没有足够侧栏空间，改为 44px 以上的“目录”触发器和独立的右侧全高抽屉；全局站点导航使用左侧全高抽屉，两个抽屉互斥。无 JavaScript 时导航退化为页面内的静态链接，不阻塞标题和正文阅读。
- 目录打开、关闭和定位只使用 transform/opacity 或原生锚点，不改变正文高度造成跳动；返回正文时恢复触发器焦点，支持键盘和屏幕阅读器。

#### 3D. 搜索与操作保持阅读位置（P0）

- 删除任何全局 `scrollTo(0, 0)` 或页面加载后强制回顶逻辑，保留浏览器默认的 `history.scrollRestoration`。复制链接、分享、主题切换、目录展开等无导航操作必须原地完成。
- 搜索提交、分类/标签筛选、排序和分页继续使用可分享的 URL 参数，但为结果区提供稳定的 `id`（如 `search-results`）；用户提交后将焦点移到结果标题/结果摘要，并仅在确有新结果时定位到结果区，而不是回到页面顶部。
- 结果为空、筛选无匹配或服务端报错时，将焦点定位到对应状态消息；有结果时保留筛选条件和页码。分页链接携带结果区锚点，浏览器前进/后退能够恢复用户上一处阅读位置。
- 后台内容库筛选、保存、发布、回收和版本恢复沿用同一原则：服务端重定向携带目标列表或目标行锚点，返回后定位到发生变化的内容；不做强制滚动，不用 AJAX 替换整页来换取表面上的连续性。
- 为锚点滚动保留 `prefers-reduced-motion` 分支；焦点移动必须可见、可解释，并通过浏览器回归覆盖鼠标、键盘和返回/前进路径。

#### 3E. 后台编辑器扩宽并增加 Markdown 工具栏（P0）

- 编辑器使用独立的宽工作区：桌面容器扩大到约 1440–1600px，三栏建议为 `220px / minmax(720px, 1fr) / 320px`；中间正文列不再被窄卡片限制，标题、摘要和 Markdown 正文拥有连续的编辑空间。
- 顶部增加固定在编辑区内的操作栏：保存状态、保存、预览、发布/定时和返回内容库清晰分组。右侧发布设置仍可折叠，滚动正文时不遮挡输入区域；小于 1024px 时收为两栏或分段面板，移动端改为单栏底部操作区。
- 在 Markdown 文本区上方增加无依赖工具栏：粗体、斜体、标题 H2/H3、引用、无序/有序列表、链接、行内代码、围栏代码、图片引用、撤销/重做和快捷键说明。工具栏通过选择区插入/包裹 Markdown，不改变 Markdown 作为唯一正文来源。
- 工具按钮必须有可见文字或明确 `aria-label`，触控区域至少 44px；支持 `Cmd/Ctrl+B`、`Cmd/Ctrl+I`、`Cmd/Ctrl+K` 等高频快捷键，插入后保留光标和选区，避免用户被跳到文本框顶部。
- 保留现有自动保存快照、字数/阅读时间、版本和服务端预览能力；不默认做实时 Markdown 解析，预览使用现有私密预览路由，降低编辑时 CPU 占用和输入延迟。
- 编辑器回归需要覆盖长标题、长 URL、代码块、中文选区、撤销/重做、工具栏键盘操作、自动保存状态和 375/768/1440px 布局。

#### 3F. 全站字体与信息密度调整（P0）

- 采用分层字号而不是全局等比例缩小：移动端正文不低于 16px；公开文章正文控制在约 17–18px、行高 1.75–1.9，阅读列保持 65–75ch，避免过大字号与过宽行长同时浪费屏幕空间。
- 收敛目前过大的展示标题和纵向留白：桌面 Hero/列表/文章标题设置更克制的上限，后台概览和页面标题同步下调；日期、标签、状态和辅助说明保持 12–14px 的清晰层级，不与正文抢注意力。
- 将顶栏、章节间距、卡片内边距、搜索表单高度和后台面板留白收敛约 15–25%，但不压缩 44px 触控目标、焦点外圈和中文正文行高。密度调整优先通过间距和标题比例完成，而不是使用小于 12px 的文字。
- 统一公开端与后台的字号 token、行高和字重，减少模板内的 `clamp` 失控；标题继续使用平衡换行和自然回退，不插入硬编码换行。
- 用真实的长标题、长中文段落、代码、表格、标签和空状态做视觉回归，确保 375px 不横向溢出，1440px 不出现大面积无效留白。
